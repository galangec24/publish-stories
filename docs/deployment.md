# Deployment

| Piece | Service | How it updates |
|---|---|---|
| API | Render web service **story-api** (free, Singapore), defined in `render.yaml` | Automatically on every push to `main` |
| Redis | Render Key Value **story-realtime** | Managed by Render |
| Database | Supabase Postgres, through the **session pooler** connection string | Migrations run when the API starts |
| Chat attachments | Supabase Storage, private bucket `chat-attachments`, created automatically | n/a |
| Website | Firebase Hosting, project **publish-stories-ph** | `npx vite build && npx firebase deploy --only hosting` from `web/` |

## Order of a release

1. Run the tests: `cd backend && python manage.py test`.
2. Push to `main`. Render rebuilds the API. Start-up runs `migrate`, `seed_genres` (only on an empty site) and `ensure_admin`, then gunicorn.
3. Wait until the new endpoint answers. For example, a new admin route should return `401` instead of `404`.
4. Build and deploy the website. It must go last when it needs new endpoints.
5. Readers switch to the new website version at their next page change. It never reloads them mid-chapter.

## API environment variables

Set these in **Render → story-api → Environment**. Values are never committed.

| Variable | Required | What it is |
|---|---|---|
| `DATABASE_URL` | yes | Supabase **session pooler** URI |
| `DJANGO_SECRET_KEY` | yes (generated by Render) | Signs tokens and the hashes of device and network IDs. Changing it signs everyone out and resets device and network grants |
| `REDIS_URL` | yes (from the Key Value) | Live updates |
| `CORS_ALLOWED_ORIGINS` | yes | The website origins (`https://publish-stories-ph.web.app,https://publish-stories-ph.firebaseapp.com`) |
| `FRONTEND_BASE_URL` | yes | `https://publish-stories-ph.web.app`, used in emails and PayMongo redirects |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | first deploy | Comma-separated admin emails. The password applies only to the first new admin |
| `GOOGLE_CLIENT_IDS` | for Google sign-in | Web (and future app) OAuth client IDs |
| `BREVO_API_KEY`, `BREVO_SENDER_EMAIL` | for email | Verification and reset codes, access-code emails |
| `GOOGLE_TRANSLATE_API_KEY` | optional | Page translator. Without it, MyMemory is used |
| `GIPHY_API_KEY` | optional | GIF search in the chat. Create the key at developers.giphy.com with platform **Web** |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | optional | Chat attachments in Supabase Storage (10 MB). Without them, attachments go in the database (3 MB). **Required** for AI readings and reels (private bucket `ai-media`, created automatically) |
| `ELEVENLABS_API_KEY` | optional | AI reading of chapters. elevenlabs.io → Profile → API keys. Billed per character read |
| `ELEVENLABS_VOICE_ID` | optional | The voice for readings (ElevenLabs → Voices → copy the voice ID). Empty: the first voice on the account |
| `HEYGEN_API_KEY` | optional | Chapter reels (presenter videos). app.heygen.com → Settings → API. Billed per video |
| `ANTHROPIC_API_KEY` | optional | Claude drafts reel scripts. console.anthropic.com → API keys |
| `PAYMONGO_SECRET_KEY`, `PAYMONGO_WEBHOOK_SECRET` | optional | Instant QR Ph checkout. Hidden from readers in test mode |
| `ACCESS_MAX_DEVICES`, `ACCESS_NETWORK_DAYS` | optional | Device cap and network sharing window for purchases (5 and 30) |
| `DB_CONN_MAX_AGE`, `JWT_ACCESS_MINUTES`, `JWT_REFRESH_DAYS`, `OTP_*` | optional | Tuning |

Do **not** set `PAYMONGO_LIVE_MODE`; the mode follows the key.

## Website build variables

Put these in `web/.env.production`, which is git-ignored. They are baked into the build:

- `VITE_API_BASE_URL=https://story-api-gmpg.onrender.com/api`
- `VITE_GOOGLE_CLIENT_ID=<web OAuth client id>`

## Keeping the free API awake

The Render free plan sleeps after 15 quiet minutes, and the next visitor waits about a minute.

- `.github/workflows/keep-warm.yml` pings `/api/about/` every 10 minutes. GitHub may delay or skip scheduled runs, and it disables them after 60 days without commits.
- More reliable: create a free **UptimeRobot** HTTP(s) monitor on `https://story-api-gmpg.onrender.com/api/about/` with a 5-minute interval. One always-on service fits in Render's free 750 hours a month.
- The real fix for production traffic is the Render **Starter** plan (`plan: starter` in `render.yaml`).

## Supabase

- **Database:** Project Settings → Database → Connection string → **Session pooler**. Daily backups are on the Supabase plan.
- **Storage:** chat attachments. The private bucket is created on the first upload. Files are only downloaded through the API.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| The first request takes about a minute | The free Render instance was asleep |
| `500` on admin pages and pooler errors | Too many database connections. Keep `DB_CONN_MAX_AGE` at 0 |
| WebSocket `403` | Missing or expired JWT, or the origin isn't in `CORS_ALLOWED_ORIGINS` |
| Readers still see an old website version | They need one page change. Firebase serves HTML with `no-cache` |
| GIF button says "isn't switched on" | `GIPHY_API_KEY` isn't set, or the deploy hasn't finished |
